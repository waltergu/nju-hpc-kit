# 集群任务自动化工作流（通用约定）

本文是**唯一通用版**，放在套件内由 AI Agent 直接阅读，**不复制到
项目里**。它假定已装好 `nju-hpc-kit`（见 `README-agent.md`）。
每个计算项目在目录里放一个 `PROJECT.md`，只写本文第 5 节规定的
项目特定内容（见套件 docs/TASK-CONVENTIONS.md）。

## 0. 与官方 skill 的分工（先读）

南京大学 e-Science 中心维护着官方聚合技能 **cicam-hpc-skill**
（git.nju.edu.cn/escience/hpc-software-source/cicam-hpc-skill），覆盖：

| 需求 | 去哪查 |
|---|---|
| Slurm/LSF 命令语法、作业提交参数、日志查看 | 官方 skill 的 `hpc-slurm` / `hpc-lsf` 模块 |
| 作业故障诊断（PEND、退出码、OOM、环境不一致） | 官方 skill 的 `hpc-troubleshooting` |
| 分区/节点/负载/价格查询、Grafana 监控 | 官方 skill 的 `query-cicam-hpc` |
| 集群使用文档检索 | 官方 skill 的 `query-doc-nju` |

**本文档不重复以上内容**，只规定官方 skill 没有的两层约定：
项目如何组织（第 1 节）、AI Agent 如何闭环管理作业（第 2–4 节）。
具体任务的验收标准与迭代规则见 docs/TASK-CONVENTIONS.md（项目内按其第 2、3 节结构落到 TASK.toml 等文件）。

## 1. 计算项目目录约定

```
<project>/
├── PROJECT.md           # 项目特定内容（仅第 5 节列出的条目；不写通用规则）
├── TASK.toml            # 任务目标与验收标准（可选；全自动模式用）
├── TASK_SPEC_REVIEW.md  # 任务描述定稿记录（用户 review 通过的文件）
├── source/              # 计算源码
├── jobs/                # Slurm 模板脚本
├── runs/                # 结果根目录（作业内经环境变量指向）
└── logs/                # Slurm 输出日志（%x_%j.out/.err）
```

文件分工与变更权限（重要）：

| 文件 | 性质 | 谁更新 |
|---|---|---|
| `TASK_SPEC_REVIEW.md` | **冻结的用户约定**：任务定义的完整描述，用户 review 通过的版本 | 只有用户确认后才变更（= 任务定义变更，重新 review） |
| `TASK.toml` | 上述约定的机读形式（字段见 TASK-CONVENTIONS.md 第 2 节） | 随 TASK_SPEC_REVIEW.md 同步变更 |
| `PROJECT.md` | **流动的操作状态**：代码入口、结果格式、活跃作业对照表、当前备注 | AI 代理每次提交作业后自动更新，可自由改写 |

约定类文件与状态类文件分离，是为了让"用户批准了什么"始终可干净地对质；
代理不得为更新作业表而反向修改 TASK_SPEC_REVIEW.md。

### 版本管理

**项目代码入 git**：项目目录应初始化为 git 仓库并配远程。
**远程选型**（按协作范围与网络条件选择，无默认唯一项）：
- 校内自用：git.nju.edu.cn（GitLab，集群直连、计算节点可用；仅限校园账号体系内用户）；
- 需要校外/国际协作：GitHub、GitLab.com 等公开托管（集群通常不可直连外网仓库，需代理或镜像中转）；
- 可两者并用（一侧为主、另一侧镜像）。

**入库规范**：
1. **入库前必须盘点目录内容**（du 等工具看清有什么、多大、是什么），禁止盲 `git add`；
2. **排除一切自动生成且可再生的产物**（结果数据、日志、各类框架/工具缓存、机器与会话状态）——**判定标准是"自动生成、可再生成"，与体积无关**；体积异常（出现远超代码体量的目录）只是警觉信号，应查明内容后决定，不得作为入库依据；
3. 方法性修正**先提交、后用于计算**，保证可追溯。

## 2. 提交作业：通用约定与陷阱

1. **计算一律经 Slurm 提交**，不在会话里前台跑长任务（>2 分钟）。
   提交命令与参数语法查官方 skill `hpc-slurm`。
   **分区归属（组内/公共）与价格以官方 `query-cicam-hpc` 的分区表
   为准**（本集群分区 AllowGroups 均为 ALL，组内/公共体现在账号与
   节点构成上：组内分区用组账号 `--account=<组账号>` 提交，公共分区
   按公共账号/QOS 规则）；二者优先级由用户指定（惯例：组内优先，
   满了再公共）。
2. **中间结果逐子单元落盘**：长计算每完成一个子单元（一次扫描中
   的单个参数取值、网格中的单个点、单个样本等）立即写/更新结果
   文件。作业被墙时截杀、节点故障后，已完成部分不丢失。
3. **`--export` 的逗号陷阱**（真实事故）：`--export=ALL,FOO=a,b,c`
   中逗号是 --export 的分隔符，`FOO` 只得到 `a`。多值参数必须
   **分号分隔 + 单引号**：
   `sbatch --export=ALL,NODES=8,'VALUES=1;2;3;4' job.slurm`；
   脚本侧解析器兼容逗号/分号两种分隔符，作业开头 `echo` 回显关键
   参数便于核验。
4. **墙时预算**：`墙时 = 单子单元实测耗时 × 子单元数 × 安全系数
   (1.5–2)`。无数实测值时先跑单个试算取数。共享分区被他人拖慢是
   常态，宁可多报 30%，不要少报被腰斩。分区墙时上限与 QoS 限制
   以官方文档/skill 为准。
5. **重型单点 / 不想预估墙时**（并非所有计算都能拆成子块）：
   a) 若计算**可拆**成可追加的子块（样本分批、网格分片、应用级
   检查点），优先拆分——墙时只需覆盖一批，被杀后从断点续跑。
   **可拆性需要针对具体任务分析**（结果对子块是否可加、块间有无
   串行依赖、每块能否独立启动），这是任务约定阶段的讨论项之一；
   b) 本集群分区无硬上限（Timelimit=infinite），直接报长墙时
   （数天）即可；公共分区注意排队优先级与资源占用；
   c) 不指定 --time 时使用分区默认值，先确认 DefaultTime 够用。
   （`scontrol update TimeLimit` 运行中上调墙时在其他集群可能可用，
   **本校实测拒绝普通用户修改**，不要依赖。）

## 3. 中断恢复协议

1. 作业超时（TIMEOUT）或失败后，读结果文件确认已完成哪些子单元；
2. 以**剩余子单元**重新提交（如 `'VALUES=10;15;20;30'`），TAG 保持
   一致便于归档；
3. 同名结果文件按"追加但不重复"原则合并；分析以文件实际内容为准，
   不依赖作业号。

## 4. AI Agent 监测闭环

- **定时轮询**：由代理会话内的定时机制触发（如每 20–30 分钟一次），
  查询用 `run-session.sh 'sacct -j <ids> ...'`（sacct 语法见官方 skill）。
- **状态机与分支**：
  - RUNNING/PENDING → 记录进度，结束本轮；
  - FAILED → 先按官方 skill `hpc-troubleshooting` 的流程诊断
    （日志、退出码、OOM），能自动修（脚本 bug、参数、资源）则修后重交；
  - TIMEOUT → 按第 3 节续跑。
- **中断恢复原则**：代理会话本身可能中断；恢复后**先查集群侧真实
  状态**（sacct/结果文件），不凭记忆推断进度，不重复提交在跑作业。
- **网络透明**：轮询走 `run-session.sh`，campus/offcampus 自动选择；
  若提示会话不存在，请用户 `start-session.sh` 后再继续。

## 5. 项目内 PROJECT.md 写什么（项目特定内容）

- 计算代码与配置入口（源码路径、环境变量约定）；
- 结果文件格式与读取方法；
- 当前活跃作业号与 TAG 对照表；
- 指向本项目的任务约定文档（按 docs/TASK-CONVENTIONS.md 第 2、3 节：目标与判据、数值质量
  门槛、诊断权责分界、何时停/改/报）。
