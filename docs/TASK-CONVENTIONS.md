# 任务约定（通用规则）

本文回答：**一个具体计算任务如何被指定、验收与迭代**。它回答"跑什么、
什么叫对、出问题怎么办、何时停下来问人"；至于"怎么跑"（提交、监测、
恢复）见同目录 `TASK-WORKFLOW.md`。

本文同样是套件内**唯一通用版**，不复制到项目。每个项目的具体约定
写在项目自己的 `TASK.toml` / `TASK_SPEC_REVIEW.md` / `PROJECT.md` 里，
按本文第 2、3 节的结构组织。

## 1. 任务指定流程（不要期望用户一次给全）

1. 用户用自然语言初述任务（大概率不完整）；
2. AI 分析还缺哪些信息（目标判据？固定设定？变化维度？预算？），
   通过讨论逐条补全；
3. 信息足够后，AI 把**完备的任务描述**写成 `TASK_SPEC_REVIEW.md`，
   请用户 review、修改、通过；
4. 通过后才生成 `TASK.toml` 并开始执行。两份文件的关系与变更权限：
   `TASK_SPEC_REVIEW.md` 是冻结的用户约定（只随用户确认变更），
   `TASK.toml` 是它的机读形式；而 `PROJECT.md` 是流动的操作状态
   （AI 每次提交后自动更新）。代理不得为更新状态而修改约定文件。
5. 执行中用户随时可修正约定；以**用户最新表述为准**，代理的记忆
   和推断不得覆盖用户的明确更正。

## 2. TASK.toml 建议字段（全自动模式必填，半自动可选）

- `goal`：目标的一句话陈述；
- `acceptance`：验收判据，写清**定性还是定量**、允许的不确定性、
  以及"判据的解释权归用户"；
- `setup`：计算设定与输入——所有固定量及其来源（实验标定、文献值、
  前序计算结果），以及对结果有影响的实现选择；
- `dimensions`：变化维度——哪些量可以/需要变化、各自范围与细化
  策略。按任务类型取意：一次性计算写"无"；收敛性研究是网格/精度
  档位；参数寻优是参数范围；生产批处理是数据分片；
- `quality`：数值质量门槛（见第 3 节）；
- `resources`：分区/账号、预算或时长约束、墙时上限；
- `stop_conditions`：何时必须停下来报告并等用户决定；
- `autonomy`：代理的自主权限边界（见第 4 节）。

## 3. 数值质量门槛（通用要求）

1. **每个计算结果必须带健康度字段**（如残差、守恒量偏差、非物理
   符号占比等），判 invalid 的阈值写进 `quality`；
2. **精度分档**（粗/中/高）：定位用低档，**验收依据必须用最高档复核**；
3. **判据要允许演化**：认知会深入、判据会升级；设计时就要预留复核
   手段——关键中间量存档原始数据、重要结论用不止一个独立判据交叉
   验证，不把可靠性押在单一阈值或单一中间量上；
4. **关键中间量直接存档**（如完整的谱/分布数据、迭代历史），不只存
   分类标签或汇总数值——出争议时随时可复核；
5. **基准量要验证放置正确**：对取值由物理约束确定（而非优化确定）
   的量，检查它是否满足约束。基准错了，下游所有量都错且不易察觉。

## 4. 诊断权责分界（哪些自动修、哪些必须问用户）

**AI 可自动处理（在约定范围内，事后报告即可）**：
- 脚本/代码 bug、环境变量与路径问题；
- 资源类：核数、内存、墙时（按第 2 节 `resources` 约束内调整）；
- 精度档位升降；
- `dimensions` 允许范围内的取值调整与重试；
- 作业失败后的重交与续跑（按 `TASK-WORKFLOW.md` 协议）。

**必须停下来问用户**：
- 验收标准的解释、放宽或变更；
- 任务目标、模型设定的调整；
- 超出约定范围的取值或资源（费用/配额相关）；
- 不可恢复操作：删除他人文件、批量杀作业、清理存储；
- 凭证与认证（任何时候）。

## 5. 决策循环（何时停、何时改、何时报）

每轮监测后：`检查 → 分析（对照 acceptance）→ 决策`：

- **符合验收** → 整理证据（判据、数值、健康度、精度档）向用户报告，
  **停下等确认**，不自行宣布任务结束；
- **不符合但可改进** → 在自主权范围内改进（实现、精度、资源，
  或 `dimensions` 允许的维度），继续迭代；**自适应是常态，不预设
  固定扫描网格**；
- **连续多轮无进展 / 触及自主权边界 / 出现约定未覆盖的情况** →
  停下，向用户报告现状、已排除的选项和建议的下一步。

## 6. 经验条款（具体任务中反复生效的规则）

- 端点筛选 + 边界细化：先用廉价判据卡出参数范围（bracket），
  再在边界附近加密确认；
- 用户对物理/领域结构的直觉优先于代理的数值标签（标签不敌对
  原始数据的直接检查）；
- 实验数据或外部结果的解读有分歧时，问用户，不擅自选择有利解释；
- 重要方法性修正（如基准量算法的修正）要追溯重做受影响的全部结论。
